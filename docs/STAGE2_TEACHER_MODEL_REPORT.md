# TNE-Core 阶段二 · 自训 encode 模型报告

> 用户要求：**不依赖外部 API，自己训练大模型做 encode**。
> 路线：我（Doubao 大模型）作为教师 → 生成九维标注数据 → 微调 MiniLM 固化成本地模型（知识蒸馏）。
> 结论：**路线可行（模型能学会教师规则），但 102 条数据不足以泛化，需扩展到数千条教师标注。**

## 一、做了什么

1. **建立爻位九维语义锚点**（`src/tne/space/semantics.py`）：
   - g1愿景 g2决断 g3产出 g4方法 g5主态 g6协作 g7输入 g8积累 g9根性
   - 三态：阳(显生发)/中和(居间稳态)/阴(隐收敛)
   - 这是"卦象语义映射逻辑"的落点，是训练 encode 的语义基准

2. **教师数据生成**（`teacher_data_gen.py`）：我（Doubao）作为教师，为 102 条多样化任务标注九维向量，覆盖 15+ 领域、各态势（生发/优化/复盘/学习/决策/执行/协作/危机/疗愈/翻译/搜索/诊断/分类/发散/修行 + 阴态收敛 + 中态稳态 + 首次无积累 + 孤立冲突 + 输入匮乏 + 根性薄弱 + 方法缺失 + 协作深依赖）

3. **微调 MiniLM**（`train_teacher_model.py`）：加载 MiniLM-L12（384维），加共享表示层 + 9 三分类头，冻结 base 只训 head

## 二、结果

| 指标 | 值 | 含义 |
|---|---|---|
| train 完全吻合率 | **100%** | 模型学会了教师的判断规则 |
| val 完全吻合率 | **10-15%** | 泛化不足（20 条留出） |
| 模型体积 | 分类头 9×3，384维输入 | 轻量可部署 |

Sanity check（新任务）：
- 「用户投诉产品有严重问题」→ `0-00-0-0-`（阴性危机 ✅ 合理）
- 「解决两个部门之间的长期矛盾」→ `++0000++0`（协作决断 ✅ 部分合理）
- 「写一首关于春天的词」→ 判成常见向量（❌ 模型偏向高频样本）

## 三、诚实结论

1. **路线可行**：模型能学会教师的判断规则（train 100%），且部分新任务判断合理。这是"自训 encode 模型"的完整通路。

2. **数据量是硬瓶颈**（v3.2 教训第三次印证）：102 条不足以泛化。模型记住了训练集但学不到九维三态空间的规律。val 只有 10-15%。

3. **要真正可用，需三选一**：
   - **A. 我作为教师生成数千条数据**（2000+ 条，需我逐一判断，工作量大但可行）
   - **B. 微调 base**（需要 GPU 或更多 CPU 时间，让 MiniLM embedding 针对九维优化）
   - **C. 结合在线 LLM**（教师 = 在线 LLM，规模更大）

## 五、下一步建议

**最有效的是 A（我生成更多教师数据）**：因为它是纯本地、不依赖 GPU/API 的路线，且我已验证模型能学会教师规则。生成 2000+ 条后，泛化有望从 10-15% 提升到可用水平。
